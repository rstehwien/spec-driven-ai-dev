# Plan: [Feature or change title]

> Template for `specs/NNN-plan.md` or `specs/NNN-<label>-plan.md`.
> Use the same `NNN` and label as the related spec.
> Each phase is a section. Update checklist states as work progresses:
> `[ ]` not started, `[-]` in progress, `[x]` completed, `[!]` blocked.
> Leave the plan current at the end of every implementation run so a new context can pick up where the work actually stands.
>
> **Budget: 300 words per phase, hard ceiling 500.** State the count when you hand this back.
> **A plan is a checklist, not a memo.** Do not open it with an inventory of the repository -
> the implementing agent can read the codebase; what it cannot derive is the intent and the order.
> Do not restate requirements from the spec, and do not re-argue decisions from the questions file.
> Where a phase depends on something surprising that already exists, or on something the spec
> assumes exists but does not, put one line with a `file:line` in that phase's Notes.
> Cap that to five lines across the whole plan; more than that means the spec needs another pass.
> Delete this blockquote before approving the plan.
