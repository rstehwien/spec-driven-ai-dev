Gridsweep, Replayed

Fourteen turns, from a 49-line spec to a finished game — one turn at a time.

Nobody filmed the original run. This is the next best thing: the fourteen commits in examples/gridsweep/, replayed in order. Each turn plays out — the prompt typed in, the agent working, the files changing — and then stops, so you can read the real diff, play the actual game as it stood at that commit, or open the commit on GitHub before moving on.

What is real: every prompt, every commit, every diff, every screenshot — read straight out of the repository, and the playable game is the code from that commit.
What is not: the pacing, and the agent's intermediate steps. Nobody recorded the tool calls, so the lines under “working” are a plausible reconstruction, not a transcript.

And then a human played it.

Eight acceptance criteria. Fifty-four automated tests. A headless-Chrome sweep driving real keys and clicks. A phase-by-phase acceptance walk. A final review. None of them could notice that the game never tells you which keys to press.

A person found it in minutes of actually playing — the same way you just did, if you opened Play the game on any of the last six turns. That finding, and the misplaced “New game” button beside it, became cycle 002.

The process is very good at holding code to a spec. It has no mechanism for noticing what the spec forgot to want — which is exactly what the human gates are for.
